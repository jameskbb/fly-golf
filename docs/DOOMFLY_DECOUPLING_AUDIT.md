# DOOMFLY decoupling audit

Date: 2026-09-13. Quick task `260913-m8r`.

Fly Golf's first neural and data stack was built on
[nftechie/doomfly](https://github.com/nftechie/doomfly) (MIT, commit
`71ecf53d78eaffaf1a57ed7b0ccf5d458abc9f33`). This audit records exactly what came from it, what
each piece became, and why. It was written **before** any change, by reading the Fly Golf tree and
its git history (every adapted file entered in `8c4446b`, the V1 putting slice) and by comparing
the files against a checkout of DOOMFLY at that commit and against the reference implementation
of Shiu *et al.* (2024) (`philshiu/Drosophila_brain_model`, `model.py`, MIT). The "after" columns
were filled in once the work was done and verified.

## The C and D items in detail

### 1. Data lock (E)

- **Current file:** `data/malecns_v1.lock.json`.
- **Upstream:** `data-provenance/malecns_v1/source.lock.json`.
- **What was taken:** the three URLs, byte sizes and SHA-256 digests. These are facts about the
  official files, re-verified by Fly Golf on 2026-09-13, but the lock said "Digests match
  nftechie/doomfly …".
- **Decision: REIMPLEMENT (regenerate).** `fly-golf-data lock` (`data/lock.py`) sends a HEAD
  request for each official object and compares the local file's size and MD5 with the bucket's
  `Content-Length` and `x-goog-hash`. It then computes SHA-256 locally, compiles the files with
  Fly Golf's compiler to record the expected counts, and writes a lock stamped
  `generated_by: fly-golf-data lock`. `fly-golf-data verify-source [--remote]` re-checks the local
  files, and optionally the lock, against the official bucket.
- **Result:** identical digests (as expected: the same official files), now with MD5, GCS
  generation and last-modified metadata, and no DOOMFLY lineage in the file.
- **Attribution:** none needed for facts. Historical mention in PROVENANCE.md and UPSTREAM.md.

### 2. Importer / compiler (C)

- **Current file (before):** `services/sim/src/fly_golf/data/prepare.py`, `select_nodes()` and
  `compile_graph()`.
- **Upstream:** `doom/connectome.py` (`exact_ids`, `index_edges`, `normalize_nodes`: retention
  policy and endpoint lookup) and `doom/prepare.py` (stable sort by source, `bincount`/`cumsum`
  row pointers, `count × sign × 0.275` weights).
- **What was adapted:** the retention policy (assigned superclass, not Glia), the
  `searchsorted`-plus-equality endpoint lookup, the stable-sort CSR build and the weight formula.
- **Decision: REIMPLEMENT.** `data/compiler.py` was written against the official release schema,
  with the node and edge rules stated as Fly Golf decisions (docs/PROVENANCE.md). New behaviour:
  full accounting of every dropped node and edge row by reason, duplicate-pair merging, validation
  of body IDs and counts, per-rule sign counts, array content hashes, and an atomic manifest.
  `prepare.py` is now only the CLI and acquisition.
- **What still coincides, and why:** three short idioms are the standard ones and match upstream:
  looking a sorted ID up with `searchsorted` and checking equality; building CSR row pointers
  with a stable sort and `bincount`/`cumsum`; and computing `count × sign × 0.275` in float32. The
  last is kept on purpose so that `weight.npy` stays byte-identical. The release order within
  each CSR row is kept for the same reason: the legacy engine depends on it, so old records keep
  replaying on a freshly compiled graph.
- **Verification:** compiling the real release with the new compiler reproduces the previously
  compiled graph **byte for byte** (`ptr`, `post`, `weight`, `counts`, `ids`) and an identical
  neuron table: 166,700 neurons, 25,582,938 edges, 124,177,617 contacts, 101 self edges and 3,718
  ambiguous-sign neurons, re-derived rather than asserted.
- **Attribution:** no DOOMFLY code remains in `compiler.py`. The rule's origin is recorded in
  UPSTREAM.md and PROVENANCE.md as history.

### 3. Transmitter-sign proxy (D)

- **Current file (before):** `brain/malecns/transmitters.py`, `transmitter_signs()`.
- **Upstream:** `doom/transmitters.py`, the same function, near-verbatim.
- **Decision: REIMPLEMENT.** A table (`FAST_SIGN`), a separate `classify()` that returns a sign
  *and a reason* (fast / conflicting / modulator-only / unclear-or-missing), whitespace-tolerant
  parsing, pandas-NA handling, and `sign_reasons()` counts for the manifest. It is covered by 33
  table-driven tests.
- **Verification:** on all 166,700 real neurons it gives the same sign as the compiled weights,
  with the same 3,718 ambiguous neurons (541 modulator-only, 3,177 unclear or missing).
- **Attribution:** no DOOMFLY code remains. The convention is recorded as a Fly Golf modelling
  assumption; that early versions followed the convention DOOMFLY and Shiu-derived models use is
  recorded as history.

### 4. LIF engine (C, kernel close to D)

- **Current file (before):** `brain/malecns/engine.py`, `_advance()` and `LIFEngine`, version
  `lif-doomfly-r2-adapted-v1`.
- **Upstream:** `doom/engine.py`, `advance()`: the same loop structure (active list, countdown
  refractory counter, ring queue), with Fly Golf's named constants, per-bin counting and reset.
- **Decision: REIMPLEMENT, and KEEP the old kernel as legacy.**
  - Phase A, freeze: `tests/lif_scenarios.py` defines 16 small deterministic networks (every case
    listed in the task, plus changing drive and a 40-neuron random network). The legacy engine's
    outputs are frozen in `tests/fixtures/lif_reference.json`.
  - Phase B, specification: Shiu et al.'s `model.py` (Brian2) is the primary specification.
    Published parameters, Fly Golf choices (constant drive instead of Poisson input; driven cells
    also refractory; float32 weight storage) and performance choices are separated in
    [LIF_ENGINE.md](LIF_ENGINE.md). The one semantic question the DOOMFLY source raised, whether a
    synapse may write `g` during refractoriness, was **checked directly in Brian2 2.10.1**. It may
    not, so dropping those arrivals is the reference behaviour, not a DOOMFLY quirk.
  - Phase C, implementation: `engine.py` (`fly-golf-lif-v1`) was written from those equations.
    It has float64 state as in Brian2, a last-spike-step refractory test as in Brian2, an exact
    propagator derived from the ODEs, ascending-index processing, an exact skip only for neurons
    at the fixed point, and one kernel call per run. It is not a translation of `advance()`.
  - Phase D, validation: identical spike trains to Brian2 on all 16 small networks, and
    **identical per-neuron spike counts to Brian2 on the full MaleCNS graph in 24 of 24 practice
    situations**. The legacy engine matched Brian2 on 15 of 16 small networks and on only 2 of 24
    full-graph situations (the two with no activity): float32 state makes about 7,800 neurons
    (median) end the 400 ms window with a different spike count. The new engine is 1.6× faster.
- **Why keep the legacy kernel:** every shot recorded before this change, and every readout
  trained before it, depends on the legacy engine's exact activity. It is kept unchanged in
  `legacy_engine.py`, selected only by version string: for `fly-golf replay` of old records, and
  for running a readout that was fitted to it.
- **Attribution:** `legacy_engine.py` is still adapted DOOMFLY code, so its MIT notice stays in
  the file header, in THIRD_PARTY_NOTICES.md and in `licenses/DOOMFLY-MIT.txt`. `engine.py`
  carries no DOOMFLY notice because it contains no DOOMFLY code; it credits Shiu et al. for the
  model.

## Training impact

The two engines' descending-neuron features correlate at only 0.84–0.99 per situation, so the
installed readout (trained on the legacy engine) is not valid on `fly-golf-lif-v1`:

- readouts now record `meta.neural_engine`; a readout without it is taken to be a legacy-engine
  readout (every one was), and `TrainedReadoutController` runs a readout only on its own engine;
- the old installed readout is archived with its engine as
  `experiments/readouts/archive/20260913T200623Z-refit.json`;
- a new readout, `20260913T220118Z`, was trained on `fly-golf-lif-v1` with the same code,
  situations and seed, from a clean checkout, and installed. It plays at the same level: 70.0 and
  71.9 strokes per nine on seeds 100–111 and 200–211, against 70.3 and 71.5 before; 45–52 % of
  holes holed out; fewer trees. The shuffled-wiring control still beats the real wiring on the
  new engine. Full comparison in [TRAINING.md](TRAINING.md#engine-migration-2026-09-13).

## Club selection audit

- `club_reach → club` (`golf/clubs.py`, `club_from_reach`): 14 evenly spaced slots, putter at 0,
  driver at 1. It is monotonic, every club is reachable and the interior slots are equally wide
  (tested). It is not biased toward any club.
- The **fixed** readout sets `club_reach = r / (r + 6 Hz)` from the mean rate of all descending
  neurons. That is monotonic in the rate, but the rate varies little between scenes, so this a
  priori mapping lands on the 6-iron almost everywhere (bench: 94 % from 20–60 m). This is a
  property of the fixed mapping and the connectome's response. It was **not** patched with a
  distance heuristic: the MaleCNS controllers still get their club only from DN activity.
- The **trained** readout picks a club with a putter gate and a club head that read DN rates only;
  club accuracy is evaluated separately from aim and power (`club_exact_pct`, `club_within1_pct`
  per kind of shot).
- The **mock** is the explicitly labelled heuristic baseline (a caddie table).
- **New telemetry:** every shot record has a `club_chain` (senses → DN rate → readout decision:
  gate probability, raw and calibrated club-head output → `club_reach` → club), shown in the
  BRAIN panel as **Club choice**, tagged FIXED READOUT, TRAINED READOUT or MOCK HEURISTIC.
