# Provenance and assumptions

This document separates what is **measured** (the connectome), what is **modelled** (the
dynamics), and what is **engineered** (the physics constants, the sensory and motor interfaces,
and the reward).

## Compiled graph

`services/sim/src/fly_golf/data/compiler.py` (`fly-golf-compile-v2`) turns the three official
files into the CSR graph. Its rules are Fly Golf modelling decisions:

| Rule | Decision | Why |
| --- | --- | --- |
| Neurons | every body with an **assigned superclass** whose status is not `Glia` | the superclass is the release's own statement that a body is a cell of a known class; bodies without one (44,877) are mostly unassigned fragments. Untraced, untyped and orphan neurons with a superclass are kept, because their synapses are real input to the rest of the network. No v1.0 body with a superclass is `Glia`; that clause is a guard |
| Edges | **every released edge between retained neurons**, no synapse-count threshold | the release already filters synapses at confidence ≥ 0.5; Shiu et al. use all connections, and any further threshold would be arbitrary |
| Self edges | kept (101) | they are in the release. With a 1.8 ms delay and a 2.2 ms refractory period they always arrive while their neuron is refractory, so they have no effect in this model |
| Duplicate (pre, post) rows | summed | v1.0 has none |
| Weight | synapse count × sign × 0.275 mV, stored as float32 | Shiu et al.'s per-synapse weight |
| Sign | ACh +; GABA, glutamate, histamine −; conflicting, modulator-only, unclear or missing: +1 (3,718 neurons) | a coarse modelling proxy, **not receptor-level physiology** (`transmitters.py`) |
| Order | neurons by body ID; edges grouped by presynaptic neuron, release order within a group | Fly Golf's engine does not depend on edge order; the legacy engine does, so this order keeps old records replayable |

Every dropped row is accounted for in `manifest.json` (125,828,298 edge rows with an endpoint
missing from the annotation table; 445,448 with an endpoint that is annotated but not
retained). These rules were first taken from DOOMFLY's importer. The compiler now implements
them from the official schema, and its output is byte-identical to the earlier compile.

Source-side filtering: synapse confidence ≥ 0.5, applied by the release.

neuPrint was not needed: the public flat files contain everything used, and no token is
required.

## Simulator ancestry

Shiu *et al.* 2024 (Brian2 LIF, MIT) → Fly Golf `engine.py` (`fly-golf-lif-v1`), implemented from
the model specification and validated against Brian2: identical spike trains on 16 test
networks, and identical per-neuron spike counts on the full MaleCNS graph
([LIF_ENGINE.md](LIF_ENGINE.md)).

History: until 2026-09-13 Fly Golf ran a kernel adapted from DOOMFLY's Numba port of the same
model (`lif-doomfly-r2-adapted-v1`, MIT). It is kept, unchanged, as `legacy_engine.py`, only to
replay records made with it and to run readouts fitted to it. Every shot record names its engine
(`controller.model`); every readout names the engine it was trained on (`meta.neural_engine`).

## Model assumptions (neural)

| Assumption | Value | Status |
| --- | --- | --- |
| Neuron model | leaky integrate-and-fire for *all* cells, including graded ones | modelling choice |
| τ_m, τ_g | 20 ms, 5 ms | from Shiu et al. |
| V_rest = V_reset, V_th | −52 mV, −45 mV | from Shiu et al. |
| Refractory, delay, dt | 2.2 ms, 1.8 ms, 0.1 ms | from Shiu et al. |
| Integration | exact solution of the linear equations each step, float64 state | as the Brian2 reference |
| Synaptic input during refractoriness | ignored (`g` is frozen) | Brian2 semantics of `(unless refractory)`, checked |
| External input | a constant drive per neuron for each 400 ms decision window; driven cells are refractory too | Fly Golf choice (the reference uses Poisson input) |
| Synaptic weight | synapse count × sign × 0.275 mV | from Shiu et al. |
| Sign | ACh +; GABA, glutamate, histamine −; conflicting, modulator-only, unclear or missing + | coarse modelling proxy, not receptor-level physiology |
| Neuromodulation, gap junctions, plasticity | none | not modelled |
| Initial state | all neurons at rest before each stroke | choice made for reproducibility |

## Physics assumptions (`golf/physics.py`, `putting-physics-v2`, practice green)

- **Surface.** A planar green `h = s_x·x + s_y·y` (small-angle), radius 12 m, with cup radius
  54 mm and ball radius 21.3 mm.
- **Rolling.** The ball rolls without slip: slope acceleration is (5/7)·g·slope.
- **Friction.** Rolling resistance is constant and calibrated from the stimpmeter:
  `decel = 1.83² / (2 · stimp_ft · 0.3048)`. A test checks that a 1.83 m/s ball rolls `stimp`
  feet.
- **Integration.** Fixed dt = 1/240 s, semi-implicit Euler. Friction clamps speed at zero, so it
  never reverses the ball. A ball at rest stays at rest when slope force ≤ friction.
- **Cup capture** (`putting-physics-v2`). Capture uses the maximum centred holing speed of 1.63 m/s from
  Holmes 1991 (*Am. J. Phys.* 59(2)), scaled by `sqrt(1 − (offset/R)²)` (our interpolation). Each pass over
  the cup is evaluated as a whole: the ball drops as soon as it is slow enough for its current offset. A ball
  that leaves the cup disc un-captured lips out once, losing up to 30 % of its speed and deflecting up to 20°,
  scaled by how centred the whole pass was. Cup crossings are checked on the swept segment, so fast balls
  cannot tunnel through. (v1 applied the lip on entry, so its lips were negligible.)
- **Not modelled.** Skid phase, grain, green undulation beyond a plane, wind and ball spin.
- **Determinism.** Python floats are used in a fixed operation order, and scenarios come from a
  seeded `random.Random`. Tests check bit-identical trajectories, including a JSON round trip.

## Reward (`putting-reward-v1`)

The reward is +1 if holed and −0.25 for a whiff. Otherwise it is the fractional distance
improvement, clipped to [−1, 1], with −0.5 if the ball leaves the green and −0.25 if it finishes
more than 1 m past the hole. It is recorded for analysis only. **No controller receives reward during play.** The only
learning in the project is the offline trained readout ([TRAINING.md](TRAINING.md)), which uses
its own practice score, never this reward, and never modifies the connectome.

## What a run record contains

Each `runs/<run_id>/shots.jsonl` line records the git commit, `git describe`, and a `dirty` flag that also
counts untracked files. These are evaluated at the time of each shot. The line also records:

- the experiment and run IDs, timestamp, git commit and dirty flag;
- the mode (`practice` or `course`), and on the course the hole, round seed, lie, target and
  running score;
- the hole seed and per-stroke controller seed;
- the controller identity (`is_mock`), its neural engine (`controller.model`) and, for trained
  shots, the readout id and the engine it was trained on; all mapping, physics and protocol
  versions;
- the full scenario and initial state;
- the sensory channels, neural summary (spikes, active neurons, per-population rates, 10 ms
  activity bins and named readouts), motor channels, decoded stroke (club, club_reach, the
  decoded launch and the launch after lie effects), the club chain (how the club was chosen:
  sensory inputs, descending-neuron rate, the readout's decision, `club_reach`, club), and the
  60 Hz trajectory with events;
- the outcome, reward and durations.

Per-bin population traces are optional (`--traces` or `FLY_GOLF_DETAILED_TRACES=1`) and are
written to `runs/<run_id>/traces/`. `fly-golf replay <run_id>` re-simulates each shot and checks
that the trajectory is identical; with `--controller` it also re-runs the brain on the recorded
sensory frame, with the engine and readout the record names, and checks the motor channels.

## The web demo's records

The web demo (Showcase Mode, [GITHUB_PAGES.md](GITHUB_PAGES.md)) replays shot records exported
from real runs by `fly-golf export-showcase`. The exporter keeps each record's fields, including
the controller identity, versions, git commit, dirty flag, neural summary, motor channels and
trajectory. It removes machine-local fields (`trace_file`, absolute paths) and rounds trajectory
samples to 0.1 mm and 0.1 ms. Each exported run names its source run id, so the original
re-simulates with `fly-golf replay`. The demo contains shot outcomes and summary neural
statistics, not connectome data.
